# レビュー観点：金額計算

課題の仕様書（3-4 料金計算・3-6 請求）をもとにまとめたもの。

## 計算

- [ ] 小計 = (単価 − 割引額) × 個数。(単価 − 割引額) が 0 円未満なら 0 円として扱っている
- [ ] 消費税 = 小計 × 税率で、1 円未満は切り捨てている（四捨五入・切り上げになっていない）
- [ ] 合計金額 = 小計 + 消費税
- [ ] 金額を `Float` で計算していない。税率はパーセントの整数（`config/hirudoki.yml` の `tax_rate_percent`）で持ち、整数の掛け算のあとに割り算する
- [ ] 税率・割引額をコードに直接書いていない。`config/hirudoki.yml` から読む
- [ ] 計算は 1 か所（モデルまたは料金計算のクラス）にまとめ、注文作成・個数変更・定期注文の生成で同じものを使っている

## 控えた値

- [ ] 注文時の単価・割引単価・合計金額を注文に保存している
- [ ] 個数変更時の再計算は、注文に控えた単価・割引単価を使い、弁当の現在の価格は使っていない
- [ ] 弁当の価格や税率を後から変えても、作成済みの注文の金額が変わらない

## 請求

- [ ] 請求額は「提供日がその月の注文のうち、キャンセル済みを除いたものの合計金額」の合算になっている（作成日ではなく提供日で絞る）
- [ ] 月の範囲は `all_month` などで日付として扱い、月末・月初の境界で漏れや重複がない

## テスト

- [ ] 割引で 0 円未満になるケース、端数が出るケース（切り捨ての確認）、税率変更後も既存の金額が変わらないケースを model spec で確認している
- [ ] 期待値は計算式から導かず、金額をベタ書きしている
